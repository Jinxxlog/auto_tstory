# R2 사진 중심 편집

## 작성과 사진 배치

본문과 사진을 같은 순서 목록으로 편집한다. 본문 블록 하나에 Markdown 문단·소제목·인용·목록·코드·표를 작성할 수 있다. 사진 뒤의 **이 뒤에 본문 추가**로 문단을 끼우고, 블록 제목을 끌거나 위/아래 버튼으로 이동한다. 각 본문 블록의 Markdown을 그대로 보관하며 전체 HTML을 다시 Markdown으로 변환하지 않는다.

사진에는 서로 다른 네 필드가 있다.

| 필드 | 용도 | 게시 여부 |
| --- | --- | --- |
| 작성 메모 | 촬영 상황·꼭 담을 내용 등 AI 참고 | 게시하지 않음 |
| 묶음 · 장소/날짜 | 선택 사진 분석을 묶는 사용자 라벨 | 게시하지 않음 |
| 짧은 캡션 | 사진의 짧은 설명 | 해당 사진의 캡션 |
| 긴 본문 설명 | 사진과 이어지는 Markdown 설명 | 해당 사진 바로 뒤 |

메모·묶음은 로컬 원고와 작업 스냅샷에는 보관한다. **사진 분석을 요청하면 선택한 사진의 메모·묶음을 AI에 전송한다.** 블로그 전송과 AI 전송의 범위는 다르다. AI가 제안한 문장은 적용 전에 검토한다.

사진 교체는 블록 ID·메모·캡션·설명·묶음을 유지하고 파일 참조만 바꾼다. 대표 사진을 교체하면 대표 참조도 갱신한다. 블록을 제외해도 과거 버전에서 쓰는 사진 파일은 삭제하지 않는다. 마지막 블록 하나는 남기며 비우려면 내용을 지운다.

## 사진 50장과 업로드

- 원고당 최대 **50장**, 장당 **10MB 이하** PNG/JPEG/WebP. 서버에서 디코딩하고 메타데이터를 제거한 PNG를 원본 자산으로 보관한다.
- 여러 파일과 폴더를 순서대로 처리하며 파일별 업로드 진행률을 표시한다. 실패한 사진은 성공한 사진을 유지한 채 개별 재시도한다. 네트워크 응답이 유실된 경우 사용하지 않는 자산이 남을 수 있으나 자동 삭제하지 않는다.
- 편집기·목록은 작은 WebP 썸네일을 사용하고 게시에는 PNG 자산을 사용한다. 썸네일은 파생 캐시이며 백업하지 않고 필요할 때 다시 만든다.
- 50장은 로컬 편집 상한이다. 50장 전체의 실제 티스토리 전송이나 고해상도 실사진 성능을 검증했다는 뜻이 아니다. 실제 전송 인수 목표는 문단 사이에 배치한 사진 10장이다.

## AI와 원고 보존

**선택 사진 분석**에서 개별 사진 또는 묶음의 앞 10장을 선택할 수 있다. 한 번의 요청은 최대 10장이다. 공급자·모델·이미지 SHA-256·작성 메모·묶음·분석 프롬프트 버전으로 캐시를 구분한다. 동일 조건은 재사용하며 바뀐 사진만 새 요청에 포함한다. 캐시·작업·결과도 로컬 DB와 백업에 포함된다.

결과의 캡션·긴 설명·확인할 내용을 검토하고 **검토한 캡션·긴 설명 적용**을 누른다. 결과를 자동 적용하거나 발행하지 않는다. 분석 후 원고 버전이 바뀌면 적용을 거절한다. 취소 이후 늦은 결과는 캐시에 저장하거나 원고에 적용하지 않는다. 중단 시 자동 재요청하지 않는다.

전체 초안 생성도 한 번에 사진 10장까지다. 블록 ID·순서를 유지한 본문/설명 결과를 요구하고 잘못된 ID는 거절한다. 부분 재작성은 하나의 본문 블록 또는 사진 긴 설명 안의 유일한 구간을 선택한다. 선택 밖의 블록·메모·사진 순서는 유지한다. 사진 10장을 넘긴 원고는 묶음별 사진 분석과 수동 편집을 사용한다.

새 블록 출력은 2026-09-23 R3 합성 세 유형의 실제 AI 생성·재작성으로 검증했다. 선택 사진 분석/캐시는 자동 계약 검사까지 수행했으며 별도 실제 AI 인수는 남아 있다. 기존 P2~P4의 실제 생성 이력을 새 기능의 성공 기록으로 재사용하지 않는다.

## 기존 데이터 전환과 되돌리기

기존 DB 전체를 일괄 변환하지 않는다. 이전 원고를 열면 **기존 Markdown 본문 블록 → 기존 순서의 사진 블록**으로 메모리에서 표현한다. 저장할 때 `schemaVersion: 2`와 블록을 가진 새 원고 버전이 생긴다. 이전 `draft_versions`의 JSON과 이미 큐에 들어간 전송 스냅샷은 수정하지 않는다. 변환 입력이 잘못되면 저장 트랜잭션을 취소한다.

새 원고에서는 블록이 원본이다. `markdown`·`images`는 검색·기존 서비스 호환을 위한 파생 표현이다. 서버는 저장 시 이 두 값을 블록에서 다시 계산한다. 본문 전체 Markdown만 덮어써서 사진 배치를 잃는 편집 경로는 제공하지 않는다.

최초 블록 저장은 DB migrations에 **6**을 기록한다. 이전 앱은 새 블록 편집 규칙을 모르므로 단순 실행 파일 교체로 되돌리지 않는다. R2 이전 앱으로 돌아가려면 변경 전 호환 백업을 복원한다. 변경 전 확보한 백업과 별개로, 새 원고의 백업도 현재 앱에서 원고·버전·원본 사진·분석 캐시가 함께 복원되는지 검사한다.

## 티스토리 전송

현재 대상은 티스토리 비공개 저장이다. 연결 계약에는 플랫폼·블로그 ID(URL)·전용 프로필·카테고리·공개 범위를 구분하고 작업에 고정한다. AI 연결은 공급자·프로필·모델의 사진 지원·연결 상태·한도를 따로 제공한다. 네이버 정식 연결과 공개 발행은 아직 지원하지 않는다.

전송기는 티스토리의 기본 사진 업로드 UI로 사진을 올리고 네이티브 사진 요소를 본문의 지정 위치로 옮긴다. 저장 전 문단·사진·캡션 순서와 제목·카테고리·비공개·대표 사진을 확인한다. 업로드 사진의 URL 경로를 작업에 남겨 재확인에서도 사진 식별자와 순서를 대조한다. 저장 후 같은 글의 본문·코드·표·사진을 다시 검사하며, 실패하면 새 글을 자동 발행하지 않는다.

## 검사와 현재 인수 상태

- `npm test`: 과거 JSON/전송 스냅샷 보존, 새 버전·블록 검증, 백업/복원, 메모 게시 제외, 사진 위치 대조, AI 블록 적용·분석 캐시 무효화·취소·오래된 결과 거절.
- 빌드 후 `npm run test:blocks`: 격리 DB·합성 PNG 50장·실제 로컬 UI/API. 업로드 실패 1건 재시도, 10장 교차 미리보기, 끌기/버튼 순서 변경, 교체, 버전 보존, 모바일 가로 넘침 검사. 외부 계정은 사용하지 않는다.
- `node --import tsx scripts/r2-private-check.ts --private-test`: 기존 블로그의 `테스트` 카테고리에 합성 10장 원고 **1개를 실제 비공개 전송**하는 명시적 검사. 작업과 결과는 `.local/r2-private/`에 격리한다. 재실행 시 확보한 글 URL이 있으면 같은 글만 확인하고, URL 없는 중단 작업은 자동 재발행하지 않는다. 원본 데이터에는 검사 원고를 추가하지 않는다.

2026-09-23 사용자 재로그인 후 실제 10장 비공개 저장·재열기·비로그인 차단을 통과했다. 최초에는 일부 사진이 티스토리 검토 안내로 표시되어 확인 대기로 유지했으며, 같은 글의 읽기 전용 재확인에서 10장 사진·식별자·순서·크기·대표 이미지·코드·표를 확인했다. 중복 발행하지 않았다. 최신 결과는 [프로젝트 작업 기록](../PROJECT_PLAN.md)을 따른다.
