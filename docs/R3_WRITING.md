# R3 여행·정보·자유 글

2026-09-23 기준. 기존 프로젝트·기술·PS에 여행·정보·자유 유형을 추가했다. 사용자가 선택한 합성 자료로 실제 ChatGPT 생성과 티스토리 비공개 전송까지 검증했다. 실제 사용자 여행 메모·원본 사진의 품질 인수는 수행하지 않았다.

## 작성 순서

1. 새 원고의 유형·제목·요약·카테고리를 입력한다. 여행은 장소, 날짜, 일정, 직접 경험, 비용을 적는다. 정보는 주제, 독자, 설명 범위, 확인 시점과 참고 자료를 적는다. 자유 글은 이야기와 분위기를 적는다. 모르는 사실은 비워둔다.
2. 사진을 추가하고 작성 메모·캡션·긴 설명을 구분한다. **유형별 개요 준비**를 누르면 빈 원고에는 기본 소제목을 제안한다. 이미 쓴 본문과 사진은 유지된다. 개요는 AI 없이 직접 검토하는 구성안이다.
3. **개요와 사진 배치 검토**에서 제목·담을 내용·사진 위치를 수정한다. 본문 편집기에서 블록을 추가할 수 있다. **개요·사진 배치 검토 완료 → 원고 저장** 후 새 유형의 전체 초안을 생성한다. 자료·블록 내용·배치·잠금이 바뀌면 다시 검토해야 한다. 수동 저장과 비공개 전송은 AI 개요 검토를 요구하지 않는다.
4. 생성 결과의 보완 질문·본문·캡션을 확인하고 적용한다. 자동 발행하지 않으며, 요청 이후 원고 버전이 바뀌면 적용을 거절한다.
5. **재작성할 블록**을 선택하고 수정 요청을 적는다. 본문 블록 또는 사진의 긴 설명 하나만 바꾼다. 캡션·메모·다른 블록은 유지한다. 같은 문장이 여러 번 나와도 블록 ID로 구분한다. 전체 생성은 사진 10장까지이며, 선택 블록 재작성은 50장 원고에서도 대상 사진 한 장만 전달한다. 본문 블록 재작성은 사진을 전달하지 않는다.
6. **AI 수정 잠금**은 전체 생성·부분 재작성·사진 분석 적용에서 해당 블록을 보호한다. 직접 편집·배치는 계속 가능하다. 저장된 원고를 미리 본 뒤 비공개 전송한다.

작성 자료·개요 목적·사진 메모·묶음은 게시 HTML에 포함하지 않는다. AI에는 글을 쓰기 위한 참고 자료로 전달한다. 유형을 바꾸어 숨겨진 이전 유형의 자료는 보존하되 생성 프롬프트에는 현재 유형의 자료만 사용한다. 사진이나 문체 예시만으로 실제 방문일·가격·가게 이름·감정을 확정하지 않도록 요청한다. 이 규칙은 사실을 자동으로 입증하는 기능이 아니므로 생성 결과의 사실 확인은 필요하다.

## 출처와 문체

정보 글은 기술 글과 같은 출처 보관 기능을 사용한다. 자동 가져오기 허용 도메인에 `korean.visitkorea.or.kr`, `www.korea.kr`을 추가했다. HTTPS·정확한 호스트·같은 origin 리디렉션·크기/시간 제한을 유지한다. 다른 사이트나 본문 추출 실패는 붙여넣기로 처리한다. 새 두 도메인의 실시간 본문 추출 성공은 이번 인수에 포함하지 않았다. 접근 시점·공식 도메인 접근과 사실 대조를 구분하며, 붙여넣기는 원본 미확인으로 표시한다.

‘나의 문체’에서 여행·정보·자유 대표 글을 등록하고 분석·확정할 수 있다. 현재 블로그의 **유형별 기본 문체**를 저장하고, 원고에서 블로그 기본값·담백한 기본 문체·유형에 맞는 확정 문체 중 선택한다. 기술 전용 문체는 다른 유형에 적용할 수 없다. 생성 작업에는 선택 당시 문체 버전과 예시 사본을 고정한다. 새 유형의 실제 사용자 문체 표본 분석은 미실행이며, 유형 분리·기본값·백업은 합성 계약 검사로 검증했다.

## 데이터와 복구

기존 원고·과거 버전·전송 스냅샷을 일괄 수정하지 않는다. 새 원고 버전에 작성 자료·개요 검토 상태·잠금·문체 선택을 저장한다. R3 필드가 있는 원고 저장 시 migrations 7을 기록한다. 블로그별 기본 문체는 `style_defaults`에 저장하고 백업에 포함한다. 이전 앱으로 돌아갈 때는 해당 앱과 호환되는 작업 전 백업을 사용한다.

이번 실제 검사는 사용자 자료와 분리한 `.local/r3-private/data`를 사용했다. 원본 DB의 원고 13개·버전 20개·사진 23개·기존 확인 대기 1건은 그대로다. 실제 블로그에는 R3 비공개 테스트 글 3개와 R2 10장 테스트 글 1개를 생성했으며 삭제하지 않았다. URL·인증·원고·사진·진단 자료는 Git에서 제외한다.

## 검증 결과

- 단위 32개, 타입 검사, 프로덕션 빌드, 개인 자료 빌드 추적 제외 검사 통과. 여섯 유형 저장·생성 적용·재편집, 반복 문장의 ID 재작성, 잠금, 오래된 결과 거절, 문체 기본값과 백업/복원 검사 포함.
- `npm run test:writing`: 격리 로컬 UI와 모의 AI 응답으로 세 유형의 입력·개요 검토 차단·사진 배치·결과 적용·메모/잠금·비공개 대기열·390px 모바일 검사 통과.
- `npm run test:blocks`: 합성 PNG 50장 업로드, 실패 1건 개별 재시도, 교차 배치·교체·과거 버전·모바일 회귀 통과. 작은 합성 PNG 성능이며 고해상도 사진 성능을 보장하지 않는다.
- `node --import tsx scripts/r3-private-check.ts --generate`: 실제 연결의 기본 사진 지원 모델로 각 유형 초안 1회와 사진 블록 재작성 1회, 총 6회 생성 성공. 사진 설명·캡션 수동 수정, 사진 순서 변경 후 원고 v4까지 보존.
- `node --import tsx scripts/r3-private-check.ts --private-test`: 검토된 세 원고를 `테스트` 카테고리에 비공개 저장. 각 2장 사진·문단 위치·캡션·대표 이미지·카테고리·비공개와 비로그인 본문 차단 통과.
- `node --import tsx scripts/r3-private-check.ts --verify`: 브라우저를 종료한 뒤 같은 3개 글의 URL·저장 사진 식별자로 읽기 전용 재확인 통과. 재발행하지 않는다.
- R2의 실제 10장 전송도 완료. 처음에는 티스토리 사진 검토 안내로 대기했으나 같은 글 재확인에서 사진 10장·코드·표·순서·대표 이미지·비로그인 차단 통과. 사진 검토 안내를 사진 불일치와 구분해 사용자 조치를 표시한다.

이 결과는 한 계정·현재 스킨·합성 자료의 인수다. 실제 여행/정보 사실의 정확성, 실제 사용자 자료·문체, 다른 PC/계정/스킨, 공개 발행은 별도 검증 항목이다. 다음 제품 단계는 R5 네이버 정식 연결이다.
