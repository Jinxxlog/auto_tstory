# Windows 로컬 설치·실행

R7.1의 배포 형태는 **소스 폴더에서 설치하는 개인용 로컬 앱**이다. 설치형 EXE, 자동 업데이트, 서버 배포는 제공하지 않는다. 다른 PC에서의 실제 계정 인수는 R7.2에 남아 있다.

## 준비

- Windows x64와 Node.js **22.20 이상인 22.x**(npm 포함). 검증 기준은 `.nvmrc`의 22.20.0이다. 다른 메이저는 SQLite·실행기 호환성을 확인하기 전 지원하지 않는다.
- 설치 시 npm 레지스트리에 접근할 인터넷 연결. 설치 후 수동 원고 작성에는 AI·블로그 계정이 필요하지 않다.
- **전체 경로에 영문·숫자 등 ASCII 문자만 있는**, 쓰기 가능한 사용자 폴더에 전체 소스를 둔다. 공백은 지원한다. `Program Files`, 압축파일 내부, 동기화·공유 폴더는 피한다. 현재 Windows Node 22.20 검사에서 한글 경로의 CommonJS 모듈 판별 오류가 재현되어 한글 사용자 이름을 포함한 비ASCII 설치 경로는 사전에 거절한다. 해당 경로 지원은 후속 호환성 항목이다.
- 티스토리 연결·전송에는 Google Chrome이 필요하다. Playwright는 잠금 파일 버전으로 설치하며 시스템 Chrome의 `chrome` 채널을 사용한다. Chrome이 없어도 수동 원고를 저장할 수 있다.
- AI를 쓰려면 실행 가능한 Codex가 별도로 필요하다. 기존 실제 생성 검증 버전은 0.153.4다. 환경 진단의 버전 검출만으로 다른 버전의 계정·모델 호환성을 보장하지 않는다. 경로가 없으면 `TSTORY_CODEX_BIN`에 실행 파일 절대 경로를 지정한다. AI 없이도 수동 작성이 가능하다.

## 설치와 첫 원고

1. `Install.cmd`를 연다. 잠금 파일 기준 `npm ci --include=dev` → 배포 빌드와 사용자 자료 추적 제외 검사 → `npm prune --omit=dev` 순으로 진행한다. Node·npm 이외의 전역 개발 패키지는 필요하지 않다.
2. 설치 완료 후 `Start.cmd`를 연다. 웹앱과 작업 실행기를 함께 시작하고 기본 브라우저에서 `http://127.0.0.1:3000`을 연다. 실행 창이 닫혀도 앱은 계속 실행된다.
3. 첫 화면의 **내 블로그 설정**에서 본인의 티스토리 주소를 저장한다. 개발자 블로그·계정은 제공되지 않는다. 계정 연결 없이 **새 원고 작성 → 제목·본문 입력 → 원고 저장**부터 사용해도 된다.
4. **블로그 연결 → 실행 환경 확인**에서 필요한 프로그램과 폴더 쓰기 권한을 확인한다. 블로그 연결과 실제 AI 사용은 별도 버튼으로 실행한다.
5. 작업을 마칠 때 **원고 저장 후 `Stop.cmd`**를 연다. 브라우저 탭을 닫는 것만으로 실행기가 종료되지는 않는다. 중복으로 `Start.cmd`를 열면 기존 실행을 재사용한다.

현재 전송은 사용자가 검토한 **비공개 새 글**만 지원한다. 최초 설치 검사는 블로그 발행을 실행하지 않는다.

## 자료와 종료

| 위치 | 내용 |
| --- | --- |
| `data/app.sqlite`, `data/images/` | 원고·버전·설정·작업·사진 |
| `.local/` | 앱 전용 로그인 자료, 진단 및 실행 상태 |
| `.local/runtime/lifecycle.log` | 시작·종료·환경 오류 요약. 자식 프로세스의 원문 출력은 기록하지 않음 |
| `backups/` | 사용자가 실행한 백업. 인증·진단 자료 제외 |

정상 종료는 작업 실행기에 종료 요청을 보내고 DB 임대를 해제한 다음 웹 서버를 닫는다. 10초 안에 종료되지 않으면 이 실행기가 시작한 자식 프로세스만 정리한다. 진행 중 발행을 강제로 끊으면 결과가 불확실할 수 있으므로 재시작 후 **작업 내역의 기존 글 재확인**을 사용한다. 자동 재발행하지 않는다.

종료 도구는 설치별 상태와 인증된 로컬 제어 응답을 확인한다. 임의의 PID나 3000 포트의 다른 프로그램을 종료하지 않는다. 강제 종료 뒤에는 임대 만료까지 최대 16초 기다릴 수 있다.

## 문제 확인

- `Doctor.cmd`: Node, 실행 의존성, 배포 빌드, 데이터/실행 상태 폴더, 3000 포트, Chrome, AI 실행 파일을 검사한다. 로그인과 발행을 실행하지 않는다. 앱 실행 중에는 포트 사용 중으로 표시되므로 앱 안의 환경 확인을 사용한다.
- 포트 충돌: 해당 프로그램을 직접 종료하거나 이미 실행한 글담의 `Stop.cmd`를 사용한다. 포트는 현재 3000으로 고정되어 있다.
- 시작 실패: Doctor 결과와 `.local/runtime/lifecycle.log`를 확인한다. 설치 실패는 같은 폴더에서 `Install.cmd`로 재시도할 수 있지만 설치 중에는 앱을 실행하지 않는다.
- 실행 상태가 응답하지 않는데 해당 프로세스가 살아 있으면 자동 제거하지 않는다. 재부팅 후 다시 실행할 수 있다. 실행 중인 폴더의 상태 파일을 임의 삭제하지 않는다.
- Chrome/AI 경고: 필요한 기능을 사용하기 전에 준비한다. 이 경고만으로 수동 원고 작성을 차단하지 않는다.

## 개발·검사와 업데이트 경계

개발하려면 `npm ci --include=dev`, `npm run dev`를 사용한다. 개발 실행은 `Ctrl+C`, 배포 실행은 `Stop.cmd`로 종료할 수 있다. `npm start`는 배포 모드의 전경 실행이고, `npm run launch/stop/status`는 CMD 파일에 대응하는 명령이다.

`npm run test:installation -- --install`은 허용한 소스만 `.local/installation-*/clean install`로 복사하고 실제 설치·빌드·개발 의존성 제거 후 최초 설정·저장·재시작·종료를 검사한다. Chrome이 없는 CI는 `--no-browser`를 추가해 API로 저장한다. 본인의 데이터나 인증은 복사하지 않으며 합성 검사 폴더는 진단을 위해 남긴다. 여러 설치 검사를 동시에 실행하지 않는다.

CI는 Windows에서 타입·단위·빌드·빌드 추적의 사용자 자료 제외·새 설치 검사를 수행하도록 정의한다. 실제 AI 생성, 로그인, 블로그 발행은 포함하지 않는다. 워크플로 파일 추가와 GitHub에서의 실행 성공은 구분한다.

업데이트·롤백 자동화와 타 PC 인수는 R7.2다. 설치 도구를 검증된 업데이트 기능으로 간주하지 않는다. 변경 전 백업·검증을 수행하고, 데이터와 `.local` 인증을 공유 소스에 넣지 않는다. 백업 복원 사용법은 [회귀·복구 기준](../REGRESSION_CHECKLIST.md)을 따른다.

## 배포·변경 기록 기준

현재 `private: true`, `license: UNLICENSED`로 명시한다. 공개 저장소라는 이유로 재배포·수정 권한을 부여하는 오픈소스 라이선스를 임의 채택하지 않는다. 외부 배포 전에 소유자가 라이선스와 제3자 의존성 고지 범위를 확정해야 한다. 현재 설치 기반 구현은 공개 배포 승인이나 출시 완료를 뜻하지 않는다.

변경은 [CHANGELOG.md](../CHANGELOG.md)의 미출시 항목에 기록한다. 출시 때 버전·지원 환경·마이그레이션·검증 결과·알려진 제한을 고정하고 PROJECT_PLAN의 실제 검증과 연결한다.
